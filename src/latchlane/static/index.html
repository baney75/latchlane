YOUR PRIVATE CONNECTION

Bring your other devices.

  1. Get Tailscale

    Create an account or sign in ↗, then install Tailscale on each device.

  2. Connect the vault host

    On the computer running this vault, run latchlane connect. Tailscale opens its supported browser sign-in when needed.

  3. Open your private address

    The setup prints your private HTTPS address. Open it on your other devices, sign in with your vault passphrase, and pair your agents.

All devices share the live vault on this host. Keep it online. Offline replicas are not created. Tailscale app OAuth is currently limited to a single tailnet; no shared OAuth secret is needed here.

MCP, WITHOUT THE SECRET

Connect a paired agent.

Pair this agent first with the command above. Then add this static local command to its MCP configuration: 

{
  "mcpServers": {
    "latchlane": {
      "command": "latchlane",
      "args": ["mcp"]
    }
  }
}

This setup contains no URL, pairing code, token, or key value. The paired credential stays in that agent’s private local profile.

YOUR PRIVATE APP WINDOW

Install Latchlane.

    Using an agent to set it up?

    Copy this prompt to an agent on this computer. It contains no key, passphrase, pairing code, or private address.

    This saves a browser app shortcut. It does not install a vault host, copy keys, or move pairings. The host must stay online; offline opens a recovery screen instead of a cached vault page.

    BRING THE LOGINS YOU CHOOSE

    Import from your password manager.

    1Password, Bitwarden, Apple Passwords, or another manager’s CSV export. Review and select up to 20 credentials at a time.

    The file is read in this browser. Only entries you select and save are sent to your vault host. The original export may contain plaintext passwords; remove it yourself when you no longer need it.

    Check the columns

    Common formats are recognized automatically. For other formats, choose the column numbers from your export. Password values are never shown in this preview.

    Nothing is selected automatically. Names must be unique. Website passwords are used only through an approved child process; they are never sent as API headers.
